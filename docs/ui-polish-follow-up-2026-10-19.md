# Journey map and interface follow-up

This is a continuing Browser audit after the initial redesign. A subsequent user review exposed issues that the original geometry and accessibility checks did not cover: atlas clusters obscured journey stops, fitted endpoints sat behind controls, and resizing could leave a route outside the useful viewing area. Passing those earlier checks did not establish a polished map.

## Changes in this pass

- Journeys now have a dedicated map source and numbered markers. Their ordered stop list, search, counts, and filters use the same journey scope. Returning to the atlas restores the full place set. An empty scoped search offers a direct search across the whole atlas.
- Nearby journey stops group according to their actual screen spacing, with at least 12px between marker edges. Group captions name the two places or the first and last stops in a larger group. Exact-coordinate records, including Mount Sinai and Wilderness of Sinai, open a chooser. The selected shared-point record retains its name on the map. Number symbols reserve collision space, and captions can choose another anchor rather than cover a marker.
- Camera fitting uses MapLibre 6's absolute padding consistently. A framed journey or selected place is fitted again when the viewport changes; manual map navigation remains manual.
- The compact landscape layout aligns a compact control pane and a separate selected-place card, exposing the map between them. Place titles can wrap, and the scale and expandable provider credits remain outside those cards. Short portrait layouts place the map key with the top tools. Camera padding uses measured geometry instead of resolved CSS inset values, which had incorrectly reserved hundreds of extra pixels after resizing a phone viewport.
- Journey navigation is available across Overview, References, and Location. Moving between places through that navigation preserves the chosen tab and resets the place-specific reference query. The journey description and itinerary use a compact disclosure so biblical context appears sooner.
- Modern road shields, transit icons, and POIs are suppressed. Journey labels take priority over duplicate modern settlement names and administrative district captions; country names remain as geographic context.
- Pointer interaction returns focus to the named map region instead of leaving it on an aria-hidden canvas. Search labels describe their current scope. The narrow desktop header uses one row.
- Journey data helpers and layer definitions are separate modules. Tests cover scope/order, filtered step numbers, coincident records, cleared/empty map data, preservation of every stop during grouping, marker spacing across scales, and stable grouping when selection changes. The obsolete route styling in the atlas layers was removed.
- Book and type facets now retain the active search, journey, and other filters when counting available results. An active choice with no results stays visible. The count check also exposed the wrong Beersheba record in Abraham's editorial guide: it now uses [OpenBible's Genesis record](https://www.openbible.info/geo/ancient/a075d61/beersheba-2), consistent with [Genesis 21:31 and 21:33](https://www.esv.org/Gn21.31%3BGn21.33%3BGn26.33%3BGn28.10/). Its coordinate is unchanged, and neither generated record was edited.
- Mobile history records which overlay is open and identifies its underlying map entry. Restoring a view does not push a new entry. Back can close a reader while retaining its selected stop, and Forward reopens it. Shared-point chooser context, passage search, and journey disclosure state are retained in local history metadata.
- The journey guide uses an explicit disclosure button with `aria-expanded` and a controlled hidden panel. It replaces an intermittent native disclosure repaint issue. Drawer focus retries after the opening transition finishes if focus has not entered the dialog; this fixes a map-opened chooser leaving focus on the page.
- Clearing a search no longer moves the clear button between pointer-down and pointer-up on compact headers. The first click clears the query, and the camera fits the restored results.

## Verification

All interaction uses the in-app Browser. Development-only map instrumentation exposes projected place positions, control rectangles, and focus events in a visible report, alongside screenshots. It checks marker/control, marker/marker, and control/control intersections; text placement still needs visual review. These reports are not a claim that every visual state is complete.

- All ten journeys passed the revised grouping and camera checks at 1440×1000, 1024×520, 900×450, 761×900, 568×320, 390×844, and 320×480. These framed views had no reported marker/control, marker/marker, or control/control intersections, and no expected stop outside the intended padding. The 320×480 pass initially caught the excessive-padding bug and was rerun after correction.
- Earlier framing passes also covered all ten at 1180×820 and 760×900. The final named-group captions were visually reviewed on desktop and small phone layouts. Captions are outside the numeric geometry report's scope.
- Final responsive-boundary checks used both Abraham's wide route and the dense Galilee journey at 500×600, 760×500, 761×501, 950×500, and 951×500. All ten checks passed framed-point and marker/control geometry. The 951×500 layout also had no horizontal document overflow.
- At 500×320, the compact header has no horizontal page overflow, and Abraham's route passed the marker and control checks.
- The four-stop Canaan group expands into smaller groups and individual numbered stops. Selecting Beersheba updates the selected record and URL. The Sinai shared-coordinate group opens the expected two-record chooser; selecting Wilderness of Sinai shows stop 3 and its selected map caption.
- Filter checks confirmed Acts gives three stops in Abraham's journey, Region narrows that to Egypt, and reset returns seven stops. Facet counts agree with those results. Reference navigation kept the References tab, reset the previous place's passage query, and preserved an expanded journey guide.
- History checks covered reader Back/Forward after a changed selection, filtered-dialog Back/Forward, leaving a journey, and Forward navigation past a restored reader to another map view. Jerusalem's `Acts 1` query retained its five matches after Back/Forward.
- A final small-phone keyboard check opened the explicit guide with Enter, moved Ur → Haran in References, closed the reader with Back, and reopened it with Forward. The References tab and expanded guide were retained.
- In the final production build, an empty `Samaria` search within Abraham's journey escaped to the whole atlas while keeping the query. The header clear action then cleared it on the first click and restored the 1,309-place count.
- Accessibility scans covered desktop Overview, References, Location, expanded and collapsed journey guides, filters, About, and the picker; phone reader, expanded guide, passage search, filters, picker, exact-coordinate chooser, restored reader, and compact expanded map key. The 18 recorded scans had zero automatic violations. Canvas-backed scale/credit contrast and the hidden journey-menu relationship remained automatic “needs review” findings; visible geometry and disclosure relationships were inspected separately.
- Atlas, Relief, and Satellite rendered with the new journey markers. Group expansion exposed the expected four separate Canaan stops, and Beersheba selected the Genesis record. Selecting Wilderness of Sinai showed stop 3. The production build was also navigated through a journey.
- Production fixtures exercised a failed map-style request followed by retry, a failed data request followed by retry, and a delayed style response. Reading Haran with an expanded guide survived the delayed map finishing. Landscape fallback actions and place browsing stayed usable. Request counters recorded two style requests for map retry, two data requests for data retry, and one style request for delayed completion.
- The latest `npm run check` passed all 31 tests, data validation, and the production build. Development audit modules and axe-core are absent from the production assets. `git diff --check` passed.
- The local Nginx production preview returned the expected MIME types, gzip, revalidation for stable filenames, immutable caching for fingerprinted assets, and 404 for missing assets. This verifies the runtime configuration locally; the Docker image itself was not run in this pass.

## Limits and handoff

Changes remain local and uncommitted. Nothing was pushed or deployed. Physical touch devices, external screen-reader software, and the deployed URL were not tested in this pass. Public tile providers still determine map availability. Manual panning and selecting a single stop can leave other, unframed stops behind fixed controls; the full-journey collision matrix applies to fitted journey views. Further independent visual review is appropriate before calling the entire product pristine.
