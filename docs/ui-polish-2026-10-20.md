# Atlas interaction and browsing polish

This continues the [journey-map pass](./ui-polish-follow-up-2026-10-19.md) and records the local UI verification. The [release code review](./code-review-2026-10-20.md) covers the final cleanup and premerge checks.

## Changes

- Atlas selection now follows its rendered group instead of drawing a second empty ring at the selected coordinate. A selected cluster names its member and says “in this group”; an individual or exact-coordinate point gets one corresponding label. Atlas layers live in `src/ui/atlas-layers.js`.
- Atlas groups have more screen spacing. Label fades no longer briefly leave several counts over a changing group. A selected modern town name is suppressed when it duplicates the biblical label; switching selection restores the original basemap filter.
- Clustering continues through zoom 18, preventing dense Jerusalem records from collapsing into overlapping individual dots at zoom 11. A native group with exactly one coordinate can open its chooser directly. Selecting another record there retains the close-up scale; Show on map also retains a closer existing zoom.
- Place browsing offers alphabetical and reference-count ordering, plus best-match ordering for searches. The header reports the total result count; loading progress stays at the end of the list. Journeys retain their editorial stop order. Reading order does not alter map grouping.
- The selected-place reminder is more compact. Short landscape layouts put search and ordering beside each other. Active filters are named in results and can be cleared without removing the query; repeated query prose was removed.
- Shared links include a validated camera tuple: latitude, longitude, zoom, and optional bearing. Manual map movement updates that state. Fitting the result set or choosing a journey clears the fixed camera. Clipboard fallback can use the address bar. Back/Forward restores layout before framing the map, avoiding a drawer animation interrupting restoration.
- Keyboard map controls now include Q/E rotation, with instructions in the map key. Escape and outside pointer interaction dismiss the key. Confidence copy distinguishes individual point colors from mixed groups.
- Journey groups update during zoom, with extra spacing during zoom-out to allow for the GeoJSON worker. A development motion recorder checks the rendered stop circles across frames.
- A short-phone CSS specificity bug that narrowed the expanded map key to 44px is fixed. The scale has an opaque background. Small atlas points and groups have phone hit areas at least 44px across; all hit areas update immediately when the layout changes, without a paint transition.
- References and Location use a compact identity/statistics header. The reference reader avoids repeated visible counts and testament headings when they add no distinction, retaining semantic headings for screen readers. Records without supplied references have one clear explanation.
- Drawer padding no longer interrupts a running journey fit at an intermediate location. Rapid list/reader interaction completes the intended destination. Sharing during a fit also captures the intended frame and then treats the captured camera as fixed.
- Short windows use the compact layout at heights of 500px or less, regardless of width. Its map controls now have a real container instead of a decorative pseudo-element; the key joins the zoom row. The expanded key stays below the desktop toolbar.
- Journey number symbols reserve collision space before captions, and names have enough offset to use vertical anchors. Portrait framing reserves room for captions near the top tools, lower key, and scale. Very short portrait journeys hide the optional distance scale to prioritize stop names.
- Nearby-group drill-down advances the scale by at least 1.25 levels when fitting alone would keep the same group. This fixes a six-stop kingdom group getting stuck at zoom 5.2 on a 320×480 viewport; successive clicks now reveal smaller groups and individual stops.
- Provider failures are remembered even when their requests finish after switching away. Returning to a failed view removes its stale source and makes a fresh request. Visible failure messages can be dismissed; compact layouts give the message a dedicated control-panel row and retain visible keyboard focus.
- Satellite uses a light biblical-label palette with a dark halo; Atlas and Relief restore the original paints. Selected names use the available bold map font. Journey outlines now share the inner line's dash spacing, keeping the path visibly schematic on imagery.
- Phone selected-place names can use two lines. Map credits and lower controls follow the actual card height, including font/layout changes. The optional distance scale is hidden in portrait windows of 500px height or less.
- The reader's outer sheet clips without becoming a scroll container, preventing focus from scrolling its header out of view. Detail tabs keep separate reading positions and begin at the top on their first visit.
- Atlas count symbols reserve marker space before captions. Selected captions retain priority over general place labels, but can be omitted where no clear anchor fits; the selected-place card continues to name the selection. This avoids drawing long captions over nearby group circles.
- `npm run preview:fixtures` serves the compiled app with controllable style/data/Relief/Satellite responses. Its separate loopback control origin stays reachable when held tiles fill the atlas origin's browser connections. No production code depends on this harness.
- Browser titles identify the current journey, explicitly selected place, or search. Back/Forward updates the title with the restored view; the default title uses the atlas's own brand description.
